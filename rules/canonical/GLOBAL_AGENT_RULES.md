# Canonical Global Agent Rules

**Source of truth:** `contracts/global-agent-policy.yaml` (policy_revision 2026-11-06-task-scoped-read-order-v1).
This file is the human-readable rendering. Per-IDE renderings live under `ide-profiles/<ide>/GLOBAL_RULES.md` and must not contradict it.

## Mandatory rules

1. **AgentCore authority.** `D:\github\agentcore-control-plane` is the single source authority. The mandatory authority baseline is `PROJECT_ANCHOR.md` → `DOC_AUTHORITY.md`. Before task work, discover every applicable `AGENTS.md` and `CLAUDE.md`, verify the exact repository, worktree, branch, HEAD, approved base, and dirty state, classify ownership, enrollment, the AgentCore/Swarm boundary, target protection, and matching approval, run the Ask-mode Foundation Report for a first repository task, and stop on unresolved scope, authority, state, or evidence drift. After the baseline, use the task-triggered read order in `docs/agent-policy/DOCUMENTATION_READ_ORDER.md` and `contracts/project-execution-policy.json`. Load `BLUEPRINT.md`, `CONTEXT_BLOCK.md`, memory/database plans, Bifrost contracts, machine-fact authority, implementation files, and historical evidence only when a matching task trigger requires them. Historical or superseded evidence is never automatic and never overrides current authority. `D:\MCP-Control-Plane` remains evidence only.
2. **One Bifrost gateway entry.** AgentCore / enrolled non-Swarm IDEs use exactly one MCP entry: `agentcore-gateway` at `http://127.0.0.1:8080/mcp` with `Authorization: Bearer ${env:BIFROST_MCP_VIRTUAL_KEY}`. Never paste the upstream registry or direct per-tool MCP entries into IDE configs. Current Bifrost runtime root: `F:\AgentCore\runtime\bifrost`.
3. **Swarm isolation.** SwarmVault and SwarmClaw are a separate execution ecosystem. Neutral shared SwarmRecall is the PC-native semantic memory/context plane and may be used by AgentCore only through the server-side agentcore-memory access facade/projection adapter; ordinary IDEs must never receive raw SwarmRecall MCP tools, database credentials, or Recall API keys. Never require SwarmVault, SwarmClaw, or Swarm-owned file roots for AgentCore / enrolled non-Swarm work. Never modify Swarm product installs. OpenClaw/ClawX are Swarm-managed and outside the AgentCore baseline. AgentCore PG18 remains canonical for exact evidence, recovery, policy, generated projections, and LangGraph checkpoints. No normal AgentCore IDE continuity on Swarm projects — HARD STOP with `swarm_project_refused`. Do not persist Swarm work through AgentCore memory, project router, or IDE profiles. A neutral dual workspace may be used only for read-only collision and boundary audits. SwarmClaw uses its own Recall adapter and native application databases; shared Recall does not merge execution authority.
4. **New Project Bootstrap.** Every new managed project runs Milestone 0 per `docs/agent-policy/NEW_PROJECT_BOOTSTRAP.md` before broad implementation.
5. **Milestone execution.** Work is organized in Milestones (outcome boundaries) with entry and exit gates per `docs/agent-policy/MILESTONE_EXECUTION_STANDARD.md`.
6. **Macro and Micro steps.** Macro steps are workstreams with Micro checklists; Micro steps are atomic and independently verifiable.
7. **Evidence-backed checklists.** Status vocabulary: `pending` / `in_progress` / `passed` / `blocked` / `failed` / `skipped_with_reason`. `passed` requires an evidence reference. Markdown checkboxes are generated projections of machine-readable state.
8. **Context Fabric checkpoints.** Capture and drift checks at every Milestone entry and exit; unresolved drift blocks closure.
9. **Arabold exact-version documentation.** Mandatory before dependency or external-API work; documentation checkpoint per Milestone.
10. **Milestone tool audits.** Audit the tool surface at every Milestone entry and exit per `docs/agent-policy/TOOL_LIFECYCLE_POLICY.md`.
11. **Progressive tool disclosure.** Only tools needed for the current project and Milestone are actively exposed. Projects begin with the Bootstrap profile. Runtime lease enforcement arrives with memory-platform M6; until then the tool manifest records desired state and agents honor it behaviorally.
12. **Write boundaries.** Write only inside the assigned repo/worktree and role-appropriate runtime roots per `docs/DRIVE_WRITE_BOUNDARY_RULE.md`. Never expose whole-drive filesystem roots. AgentCore runtime is under `F:\AgentCore\runtime`. Never expand AgentCore write authority into `H:` or `E:\Swarm\...`. Never format or re-provision `H:`.
13. **Secrets.** Windows User-scope environment variables only. No `.env` files. Never print, store, or commit secret values. Missing variable → stop and report the name.
14. **No direct database access.** Normal IDE agents never connect to PostgreSQL, SwarmRecall PG16, or Meilisearch directly and hold no database credentials. Memory flows through `agentcore-gateway` -> `agentcore-memory`; semantic memory/context then reaches neutral SwarmRecall server-side.
15. **Git safety.** Push after every completed task with narrow validation and a secret/junk scan first. Never pull/fetch/merge/rebase or force-push without explicit operator instruction. See `docs/GIT_PUSH_ONLY_POLICY.md`.
