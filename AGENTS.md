## Operating Rules

- **Execution ownership:** The AgentCore authority-maintainer (Codex for the current alignment and production-hardening work) owns architecture, protected authority/contracts, renderer-to-runtime wiring, security boundaries, live rollout, final validation, and Git integration. Cursor is a bounded implementation and independent-review surface, not the default owner of the full build. Give Cursor the final goal, exact authority paths, scope, acceptance contract, and stop gates; let it choose implementation details only inside that boundary.
- **Agent routing is mandatory, not optional:** For non-trivial code changes, Codex remains the main engineer and must own problem framing, root-cause analysis, design choices, task decomposition, acceptance criteria, review, and final verification. AgentCore implementation workers write routine feature code, focused bug fixes, tests, and refactors inside the bounded prompt Codex gives them. Morph is used for external GitHub/source-pattern discovery and surgical file application when it materially improves correctness, migration safety, or edit precision. Do not let Cursor, Morph, or an implementation worker create architecture authority, expand scope, weaken policy, or decide the global solution.
- **Direct Codex editing exception:** Codex may edit directly only for trivial fixes, test harness corrections, glue around a worker-produced patch, emergency recovery, or when the required worker/Morph tool is unavailable or fails to produce a usable patch. Record that reason in the work summary and keep the edit narrowly scoped.
- **Prompt contract for delegated code work:** Every worker/Cursor/Morph implementation prompt must include the verified root cause, exact files or authority paths, non-goals, rollback or stop gates, required tests/evidence, and the instruction to solve the underlying issue rather than only the visible symptom. Do not provide low-level implementation steps unless the boundary or safety contract requires them.
- **Cost-control stop rule:** If a delegated agent repeats the same failure, emits the same plan without new evidence, or asks for the same missing context twice, stop that agent/session and return control to Codex for a smaller bounded prompt or a different worker. Expensive model use must be deliberate, bounded, and tied to evidence that cheaper workers or deterministic tooling are insufficient.
- Work primarily in this repository unless the user explicitly authorizes live rollout.
- Do not edit live client configs during repo-only phases.
- Create a timestamped rollback copy before editing existing managed files.
- Use unlock -> edit -> validate -> re-lock for managed files.
- Patch Bifrost renderers/`scripts/bifrost/render_bifrost_config.py` first when generated outputs would otherwise drift. (`scripts/mcp_control_plane.py` is archived under `docs/archive/`.)

- Respect `AUTHORITY_LOCK.md` and `contracts/authority-lock.yaml`. Operator-locked files require authority-maintainer approval, rollback evidence, validators, and independent review. Generated projections remain read-only to ordinary agents.
- Keep the Swarm relationship through `docs/boundaries/SWARM_FOREIGN_BOUNDARY.md` and `contracts/foreign-ecosystem-boundaries.yaml`. SwarmClaw/SwarmVault mutable facts belong to `D:\github\swarm-ecosystem-control`. - **Git policy:** Commit and push after every completed Milestone or substantial standalone change (new feature, infrastructure change, policy/contract update, validator fix, renderer change). Do not ask permission for these routine post-task commits — just validate, scan, stage source-controlled files, commit with a concise message, and push `origin main` (or the active task branch).
